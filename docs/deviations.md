# Deviations

This file tracks every intentional departure from the manuscript. Each row gives the paper anchor, the code anchor, the deviation, and why we made it.

| Paper anchor | Code anchor | Deviation | Justification |
| ------------ | ----------- | --------- | ------------- |
| Sec. V.C (precision not stated) | `configs/main.yaml` `train.precision = bf16` and `cartidt/backend/trainer.py:TrainLoop._micro_step` | We pick **bf16 autocast** as the canonical training precision. | The manuscript reports A100 80GB hardware and a 38-hour wall-clock but never names the dtype. bf16 is the default DINOv2 fine-tuning recipe, has no loss-scaling, matches A100's TensorCore native support, and is the only choice that fits 38 h with `effective batch = 32` on 4 GPUs at the stated 160 × 384 × 384 volume size. fp16-autocast and tf32 alternatives are documented in `docs/project-context.md §7` and can be selected via `train.precision`. |
| Sec. III.D-4 (GraphSAGE [15]) | `cartidt/passes/twin/graph_sage.py` | We use a hand-rolled GraphSAGE rather than depending on `torch-geometric`. | The graph has 14 nodes and 26 edges — `torch-geometric` would add a heavyweight dependency for a layer that fits in 40 lines. The hand-rolled layer reproduces the SAGE update equation in Sec. III.D-4 Eq. (4) verbatim with edge-weight scaling. |
| Sec. III.D-2 (node taxonomy) | `cartidt/passes/twin/anatomy_graph.py` | The exact mapping from the 14 graph nodes to the 6 segmentation-class labels is recorded in `CartiDTConfig.node_to_label`. | The manuscript names the 14 sub-regions in prose (Sec. III.D-2 ¶2) but does not draw the explicit `node_id → label_id` table. We commit a deterministic table so the implementation is reviewable and the `compartment_masked_gap` operator is reproducible. |
| Sec. V.C augmentations (random elastic — parameters not stated) | `cartidt/frontend/conditioning/spatial_aug.py:VolumeAugmentConfig` | We use `(sigma=8.0, alpha=12.0)` as the elastic field hyperparameters. | The manuscript states "random elastic" without parameters; these values follow MONAI's default `Rand3DElastic` and are used in the IWOAI 2019 reference pipeline cited as ref. [2]. |
| Sec. III.D-2 final ¶ (edge weights computed once from mean training seg) | `cartidt/passes/twin/contact_weights.py` (called offline) + `cartidt/link.py` registers the result as a non-persistent buffer | We expose the estimator as a one-shot function rather than running it inside the training loop. | The manuscript pre-computes weights once and freezes them; running the estimator inside the loop would consume the dataset twice per epoch with no benefit. |
| Sec. V.C ("PyTorch 2.1") | `pyproject.toml` pins `torch==2.1.2` | We pin the patch level. | Patch-level pinning gives bit-reproducibility across machines. PyTorch 2.1.2 is the most recent 2.1.x release with the cuDNN attention kernels DINOv2 relies on. |
